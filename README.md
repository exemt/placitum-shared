# placitum/shared

Общий код процессов Placitum: то, что у всех инспекторов и сервисов значит одно и то же.

Правило приёма простое: сюда попадает код, **у которого один смысл на весь контур и один
хозяин**. Как только у него появляется «а у нас иначе» — он остаётся в компоненте.

## Что внутри

| Пакет | Что делает |
| --- | --- |
| `pulse` | кадр присутствия на `WAF_STATUS`: кто, где, сколько работает. Не вердикт и не healthcheck. Шапка `Frame` встраивается в кадр любого процесса, `Message` — кадр инспектора |
| `host` | снимок машины для этого кадра: ядра, память, нагрузка |
| `flow` | счётчики ввода-вывода: сколько принято и отдано за окно |
| `loglevel` | словарь уровней журнала nginx (`debug`…`alert`), его разбор и стартовый порог из переменной процесса |
| `logkit` | журнал сервиса: строки в `waf.log` пачками `kind=log`, живой порог по документу `policy/log-levels` |
| `dataset` | запись в активные наборы через keeper: синхронно у HTTP-процессов, в фоне у инспекторов |
| `netinfo` | клиент кодера гео: анонсы, состав системы, кэш и отрицательный кэш |
| `geopb` | сгенерированный gRPC-клиент кодера; `geo.proto` — копия контракта, регенерируется у кодера |

## Зачем он появился

Двенадцать пакетов лежали копиями в девяти модулях инспекторов — около 58 тысяч строк почти
одинакового кода, — и копии уже расходились: `flow`, `host` и `pulse` у двух инспекторов
совпадали байт в байт, а `queue`, `protocol` и `logsink` — нет.

Цена расхождения известна: конверт секретов однажды был реализован трижды, версии разошлись, и
раскатка не работала вовсе при полностью исправном ключе. Общий пакет — способ, чтобы такое
не повторялось молча.

## Как подключают

```go
import "github.com/exemt/placitum-shared/pulse"
```

```sh
go get github.com/exemt/placitum-shared@v0.3.0
```

Компонент **пинует версию** в своём `go.mod` и обновляет её, когда ему нужно. В платформе рядом
лежит `go.work`, поэтому правка здесь видна компонентам сразу, без выпуска версии; в поставочную
ветку `go.work` не попадает, и сборка образа идёт по пину.

Кадр присутствия у каждого процесса свой: у инспектора адреса в нём живые наборы, у капчи —
счётчики вердиктов, у keeper — наборы, у агента Redis — снимок хранилища. Общий кадр от этого не
растёт: процесс встраивает `pulse.Frame` (сервис) или `pulse.Message` (инспектор) в свою
структуру и шлёт её `pulse.PublishFrame` — поля лягут в тот же объект JSON.

## Чего здесь нет

- **Решений инспектора:** профили, условия, вердикты, пороги, политика. Это и есть компонент.
- **Разбора `inspector.conf` и цепочки окружения**, очереди и дедлайнов, схемы сообщений шины,
  поколения из KV, отправки событий аудита. Они общие по смыслу, но сегодня в девяти копиях
  разошлись именами переменных и полями; их переносят по одному, приводя к общему виду —
  это следующие версии.

## Версии

Семвер. Мажор не ломается ради удобства: полтора десятка компонентов не переписываются разом.
Обновление контракта шины — отдельный разговор: там порядок обратный, сначала все читатели,
потом писатели.

## Ветки

`develop` — то, что разрабатывается: сюда приезжает каждая выкладка. `main` — выкаченные сборки.
Правок в этом репозитории не делают: обе ветки производные от платформы.
